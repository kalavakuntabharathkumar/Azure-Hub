# Azure Hub-Spoke Infrastructure Automation with Terraform

Terraform-based reference implementation for a small Azure hub-and-spoke network.

## What it provisions
- Hub and spoke VNets with four subnets in total
- NSGs with explicit inbound/outbound rules
- Two Ubuntu Linux VMs in the spoke network
- Standard public Load Balancer and backend pool
- VNet peering, route tables, and optional VNet-to-VNet VPN gateway resources
- Network Watcher diagnostic workflow and troubleshooting runbook

## Layout
- `modules/network`: VNets, subnets, peerings, NSGs, route tables
- `modules/compute`: Linux VMs and NICs
- `modules/load-balancer`: frontend, backend pool, probe, and rule
- `modules/vpn`: optional VPN gateway and connection resources
- `environments/dev`: example environment inputs
- `scripts`: validation and connectivity checks
- `docs`: architecture and troubleshooting notes

## Usage
1. Install Terraform >= 1.6 and Azure CLI.
2. Run `az login` and select the intended subscription.
3. Copy `environments/dev/terraform.tfvars.example` to `terraform.tfvars` and set unique names, region, and SSH public key.
4. Run `terraform init`, `terraform validate`, `terraform plan`, then `terraform apply`.

VPN gateway creation is enabled by a variable and can incur significant Azure cost and deployment time. Keep it disabled for a low-cost network-only test. Never commit credentials, private keys, or real tfvars files.

## Notes on the reported timing
The project brief describes a five-run comparison of manual portal setup (~40 minutes) and Terraform deployment (~9 minutes), with no planned drift after apply. Treat those figures as measurements to reproduce in your own subscription; they are not generated by this repository.
